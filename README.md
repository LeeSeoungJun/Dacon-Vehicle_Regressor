# 전기차 가격 예측

차량의 제조사·모델·상태·배터리용량 등의 정보로 **가격(백만원)**을 예측하는 데이콘 회귀 프로젝트입니다. [분석 노트북](전기차가격예측.ipynb)에서 데이터 분포 확인, 결측값 처리, OLS 분석, 세 가지 트리 모델의 검증, 제출 파일 생성까지 진행합니다.

이 문서는 현재 노트북의 코드·주석·저장된 출력과 [모델 비교 결과](model_comparison.csv)를 기준으로 작성했습니다. **설정의 역할과 실제 선택 근거를 구분**하며, 기록되지 않은 튜닝 과정이나 성능 개선 이유를 추정하지 않습니다.

## 데이터와 검증 설계

- `train.csv`: 7,497행, 11열. `가격(백만원)`이 예측 대상입니다.
- `test.csv`: 노트북 출력 기준 846행. 정답 가격이 없는 제출용 데이터입니다.
- `ID`는 예측 변수에서 제외하고 제출 시 식별자로 사용합니다.
- 입력은 제조사, 모델, 차량상태, 배터리용량, 구동방식, 주행거리(km), 보증기간(년), 사고이력, 연식(년)입니다. 이후 주행거리를 제거합니다.

학습 데이터를 `train_test_split(test_size=0.2, random_state=3000)`으로 나눕니다. 학습 5,997행, 검증 1,500행이며 세 모델 모두 같은 분할을 사용합니다. 분할을 전처리보다 먼저 수행하고, 결측 대체값·표준화 기준·인코딩 열은 학습 데이터에서 정해 검증 및 제출 데이터에 적용합니다.

8:2 비율과 시드 3000은 기존 설정을 유지한 값입니다. 특정 비율이나 시드가 더 우수하다는 비교 실험은 기록되어 있지 않습니다. 시드 고정은 같은 조건으로 분할을 재현하기 위한 설정입니다.

## 전처리: 무엇을 했고, 근거는 어디까지인가

### 1. 분포 확인과 배터리 결측값 대체

주행거리와 배터리용량에 대해 각각 `bins=25`, `kde=True`인 히스토그램을 그립니다. 25는 시각화 구간 수이며 모델의 하이퍼파라미터가 아닙니다.

배터리용량 결측값은 다음 순서로 채웁니다.

1. 학습 데이터의 **같은 차량 모델별 배터리용량 중앙값**
2. 해당 모델의 중앙값으로 채우지 못하면 **학습 데이터 전체 배터리용량 중앙값**

구현상 차종별 대표값을 먼저 적용하고, 모델별 관측값이 없는 경우 전체 대표값으로 보완하는 구조입니다. 중앙값은 극단값의 영향을 평균보다 덜 받는 통계량이지만, 이 저장소에 평균 대체·중앙값 대체의 성능 비교는 없습니다. 중앙값 선택을 실험으로 입증된 최적 방식으로 해석하지 않습니다.

### 2. 그룹별 가격의 3표준편차 기준

학습 데이터에서 `차량상태 → 구동방식 → 사고이력` 순서로 각 그룹의 가격 평균과 표준편차를 계산하고, 아래 조건을 만족하는 행을 남깁니다.

```text
|가격 - 그룹 평균| ≤ 3 × 그룹 표준편차
```

각 단계는 앞 단계에서 남은 데이터로 다시 계산합니다. 표준편차가 결측이면 0으로 처리합니다. 검증 데이터는 제거하지 않습니다.

이는 그룹별 가격 분포를 기준으로 극단적인 관측값을 걸러내는 기존 접근입니다. **3이라는 임계값의 탐색·비교 기록은 없고, 저장된 실행에서는 처리 후에도 학습 데이터가 5,997행이므로 실제 제거된 행은 없습니다.** 따라서 이 처리로 성능이 개선되었다고 주장할 수 없습니다.

### 3. 표준화와 원핫 인코딩

- 수치형 입력에 `StandardScaler`를 학습하고, 같은 기준으로 검증·제출 데이터를 변환합니다.
- 모델·제조사·차량상태·구동방식·사고이력은 `pd.get_dummies(dtype=float)`로 원핫 인코딩합니다.
- 검증·제출 데이터는 학습 열 순서에 맞추고 없는 열은 0으로 채웁니다. 학습에 없던 범주의 추가 열은 이 과정에서 제외됩니다.

표준화는 수치 변수의 척도를 맞추며, 원핫 인코딩은 범주를 숫자 크기의 순서 없이 표현합니다. 표준화는 기존 분석 흐름을 유지한 처리로, 세 트리 모델에서 필수이거나 성능을 높였다는 실험 결과는 없습니다. 저장된 출력에서 인코딩 후 입력은 40열이며 주행거리 제거 후 트리 모델에는 39열이 사용됩니다.

## OLS 분석과 주행거리 제거

OLS는 계수와 유의확률을 확인하는 분석 단계입니다. 절편을 추가하고, 완전 공선성을 줄이기 위해 **OLS에서만** 제조사 더미 열과 각 범주군의 기준 더미 하나씩을 제외합니다. 노트북 주석은 제조사가 모델에 종속된다는 점을 제조사 제외 이유로 명시합니다. 트리 모델에서는 제조사와 모델 더미를 모두 유지합니다.

저장된 OLS 출력은 다음과 같습니다.

| 항목 | 저장된 값 | 해석 범위 |
| --- | ---: | --- |
| 학습 관측 수 | 5,997 | 검증 성능이 아닌 학습 분석 |
| R² | 0.990 | 학습 데이터에 대한 설명력 |
| 주행거리 계수 | 0.1139 | 표준화된 주행거리의 선형 계수 |
| 주행거리 p-value | 0.293 | 이 OLS 설정에서의 유의확률 |

이어지는 셀은 “유의하지않은 변수 삭제”라는 주석과 함께 주행거리를 학습·검증·제출 입력에서 제거합니다. p-value 0.293은 통상적인 0.05 기준보다 크지만, **노트북에 유의수준을 명시한 선택 규칙이나 주행거리 포함/제외 성능 비교는 없습니다.** 다른 변수의 p-value가 크더라도 함께 제거하는 구현은 아닙니다. 이 결과만으로 주행거리가 가격에 영향이 없거나 트리 모델에서도 불필요하다고 결론 내릴 수 없습니다.

## 모델과 선택한 설정

동일한 전처리와 검증 세트로 Random Forest, XGBoost, LightGBM을 각각 학습합니다. 세 모델은 여러 결정 트리를 결합하는 회귀 모델이며, Random Forest는 여러 트리의 예측을 평균하고 XGBoost와 LightGBM은 부스팅 방식으로 학습합니다.

| 모델 | 코드에 명시된 설정 |
| --- | --- |
| `RandomForestRegressor` | `random_state=3000, n_jobs=4` |
| `XGBRegressor` | `random_state=5024, n_jobs=4` |
| `LGBMRegressor` | `random_state=3000, n_jobs=4, verbosity=-1` |

- `random_state`는 모델 내부의 무작위성을 고정합니다. **3000과 5024를 선택한 개별 근거나 시드별 비교는 기록되어 있지 않습니다.**
- `n_jobs=4`는 병렬 작업 수 설정입니다. 예측 성능을 위한 탐색 결과로 기록된 값은 아닙니다.
- LightGBM의 `verbosity=-1`은 로그 출력 제어 설정입니다.
- 트리 수, 깊이, 학습률 등은 생성자에서 별도로 지정하지 않습니다. 설치된 라이브러리 버전의 기본값을 사용하므로, 이를 직접 튜닝해 고른 값으로 표현하지 않습니다.

현재 노트북에는 Grid Search, Random Search, 교차검증, 조기 종료, 앙상블 결합이나 하이퍼파라미터 탐색 이력이 없습니다. 확인 가능한 실험 범위는 **현재 설정의 세 모델을 한 번의 고정된 분할에서 비교한 것**입니다.

## 저장된 검증 결과와 최종 모델

평가 지표는 `sqrt(mean_squared_error(y_val, 각 모델의 예측값))`로 계산한 RMSE입니다. 가격과 같은 백만원 단위이며 낮을수록 좋습니다.

| 모델 | 검증 RMSE(백만원) |
| --- | ---: |
| Random Forest | 1.3677186078910624 |
| XGBoost | 1.4009418755041476 |
| LightGBM | **1.3441522938124364** |

위 수치는 노트북 출력과 `model_comparison.csv`에 저장된 값입니다. 이 README 수정 과정에서 모델을 새로 실행해 얻은 수치가 아닙니다.

이 분할에서는 LightGBM의 RMSE가 가장 낮습니다. 다만 최종 셀 주석은 **기존 최종 LightGBM 제출 흐름을 유지한다**고 명시합니다. 점수에 따라 모델을 자동 선택하는 코드가 아니므로, 새 비교 실험을 통해 최종 모델을 처음 결정했다고 서술하지 않습니다.

제출 단계에서는 전처리된 학습·검증 입력과 정답을 합쳐 LightGBM을 다시 학습하고 `result13.csv`를 생성합니다. 이때 결측 대체·표준화·인코딩 기준은 앞서 학습 부분에서 정한 것을 유지하며 전체 원자료로 전처리를 다시 학습하지 않습니다. 제출 파일의 ID 순서가 `sample_submission.csv`와 같은지, 행 수가 맞는지, 예측값이 모두 유한한지 검사합니다.

기존 README에 기재된 대회 기록은 **74위 / 1,314명(상위 약 5.6%)**입니다. 저장소에서 해당 순위의 리더보드 증빙이나 제출 점수·제출 파일과의 대응은 확인되지 않으므로, 과거 기재 기록으로만 남깁니다. 위 로컬 검증 RMSE가 그 순위에 해당하는 대회 점수라는 의미는 아닙니다.

## 해석의 한계와 다음 검증 과제

현재 결과는 무작위 단일 검증 분할에 한정됩니다. 모델 비교에 사용한 검증 세트이므로 독립 최종 테스트 성능으로 표현하지 않으며, 신규 차종이나 미래 시점 가격에 대한 일반화도 검증하지 않았습니다. OLS 계수는 인과관계를 뜻하지 않습니다.

중앙값 대체, 3표준편차 기준, 표준화, 주행거리 제거의 개별 효과를 주장하려면 같은 검증 조건에서 각 처리를 바꾸는 비교가 필요합니다. 여러 분할 또는 교차검증을 통한 안정성 확인, 명시적인 하이퍼파라미터 탐색, 전체 데이터 기반 전처리 재학습은 후속 과제이며 현재 수행된 실험에 포함하지 않습니다.

`requirements.txt`는 버전 하한만 지정하므로 설치 시점에 따라 기본 파라미터와 수치 결과가 달라질 수 있습니다. 정확한 재현에는 실제 실행 환경의 버전 고정이 추가로 필요합니다.
